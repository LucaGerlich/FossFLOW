# Platform phase 1: the foundation

## Context

FossFLOW is one editor today. You save to `localStorage` or a flat folder of JSON files (`packages/fossflow-backend/server.js`), move landscapes around by export and import, and the Beszel login lives in a `.env` file behind nginx Basic Auth. There are no users, roles or database.

Phase 1 turns it into a self-hosted platform modelled on n8n, with **landscapes in place of n8n's workflows**:
- people log in;
- roles exist at instance level and per project;
- landscapes are stored on the server per project, with no more file shuffling;
- live-data logins become **encrypted credentials** for pluggable **connectors**.

Beszel is the first connector, and more will follow. Plain FossFLOW (a static build with local saving and no backend) keeps working unchanged.

**Agreed in conversation:**
- the n8n model (Overview, personal space and team projects, credentials, users, Settings);
- instance roles Owner, Admin and Member, plus project roles Admin, Editor and Viewer;
- custom roles come in phase 4, on the same permission scopes, so no rework;
- foundation first;
- stack: **NestJS, PostgreSQL, Drizzle and better-auth**;
- hairline blocks stay.

Out of scope, for later phases:
- the flows workbench (phase 2);
- folders, tags, favourites, version history and sync history (phase 3);
- custom roles, API keys, two-factor login, policies and audit log (phase 4);
- single sign-on, LDAP, external secret stores, Git and log streaming (phase 5);
- sharing credentials across projects;
- public read-only links;
- real-time co-editing.

## Architecture

**Server** (`packages/fossflow-backend`, rewritten in place as a NestJS app under `src/`; the Express `server.js` is removed). Modules:
- `config`: env validated with zod. `DATABASE_URL`, `FOSSFLOW_URL`, optional `FOSSFLOW_ENCRYPTION_KEY`, optional `SMTP_*`, `BACKEND_HOST`, `BACKEND_PORT`.
- `database`: Drizzle with `pg`; migrations run on boot.
- `crypto`:
  - One master key. If unset, a key is generated once into `/data/config/encryption-key` (mode 0600) and a loud "back this up" message is logged, as n8n does.
  - Per-purpose keys are derived with HKDF: `credentials-v1`, and the better-auth secret.
  - Ciphertext is stored as `v1:` + base64(12-byte IV, 16-byte tag, ciphertext) with AES-256-GCM, so keys can be rotated later.
- `auth`: better-auth configuration.
  - Email and password, with `disableSignUp: true`.
  - `trustedOrigins` and `baseURL` from `FOSSFLOW_URL`; `trustedProxyHeaders` on, since only the loopback nginx reaches the server.
  - A global `SessionGuard` with a `@Public()` opt-out.
  - An origin check on all mutating `/api` requests (CSRF).
- `setup`: `POST /api/setup/owner`, which works only while there are no users.
- `users` and `invitations`:
  - Invite links are 32 random bytes, stored only as a SHA-256 hash and valid for 7 days. The admin can copy the link; it's emailed too when SMTP is configured (nodemailer).
  - Accepting an invite sets the name and password.
  - Admins can copy a password-reset link.
  - Instance role changes.
  - Deleting a user offers to transfer their landscapes and credentials. The last Owner can't be deleted.
- `rbac`:
  - A `roles` table: slug, scope (`instance` or `project`), a `scopes[]` list, and a `system` flag.
  - It is seeded with `global:owner`, `global:admin`, `global:member`, `project:personalOwner`, `project:admin`, `project:editor` and `project:viewer`.
  - Scopes use n8n-style names, e.g. `landscape:update`, `credential:use`, `projectMember:manage`.
  - A `@Scopes()` decorator plus a guard work out the effective scopes: the instance role, merged with the project role for the project resolved from the route. Owner and Admin get every project scope.
- `projects`:
  - A personal project is created for each user through a better-auth `databaseHooks.user.create.after` hook.
  - Owners and Admins create team projects.
  - Members and their roles.
  - Deleting a project transfers or deletes its contents.
- `landscapes`:
  - CRUD, and moving between projects.
  - Each landscape stores its `model` as jsonb with an integer `version`. A `PUT` must send the version it is based on, and a mismatch returns **409** with the server's version, so nothing is silently overwritten.
  - Server-side validation checks the top-level shape with zod and enforces a 10 MB limit. The full model schema stays in the lib. *Ponytail:* this is a shape check; full validation can move server-side if bad data ever gets through.
  - Only imported icons are stored. Icon packs are merged on load, exactly as local save does today.
- `credentials`:
  - CRUD, a test on save, and secret fields are never returned (the API shows `••••` for them).
  - Each credential belongs to one project. Editors and above get `credential:use`; Viewers see only the name.
- `connectors`:
  - A registry of `Connector`s. Each defines an `id`, a name, a credential form descriptor (fields, labels, which fields are secret, a zod schema), `test(config)` and `fetchInventory(config) → LiveSystem[]`.
  - The first is `beszel`, built from the existing pure code:
    - `live/beszel.ts`, `live/normalize.ts` and `live/config.ts` (URL validation) move unchanged, apart from their import suffixes;
    - their tests move to Vitest.
- `live`:
  - A source manager runs one hub per credential that is attached to at least one landscape. It reuses `live/hub.ts`, generalised so the source id is the credential id instead of the hard-coded `'beszel'`.
  - Hubs start and stop when attachments change.
  - `GET /api/landscapes/:id/live` merges the snapshots of that landscape's sources. It requires `landscape:read`.
  - `LiveSystem` gains a `kind` (`host` for Beszel). New kinds arrive with new connectors.
- `migration` (runs once, on first start):
  - The files in `/data/diagrams` are imported into the Owner's personal project.
  - If `BESZEL_*` env vars are present, a "Beszel" credential is created from them.
  - Live keys in the imported landscapes are rewritten from `beszel:` to the new credential id.
  - A log line then says the old variables can be removed.

**Data model.** better-auth's four tables, with `user.instanceRole` added through `additionalFields` (not writable by clients), plus:
- `roles`;
- `projects` (`type`: `personal` or `team`);
- `project_members`;
- `landscapes`;
- `credentials` (`project_id`, `type` = connector id, `data` encrypted);
- `landscape_sources`;
- `invitations`;
- `meta`, for migration flags.

**App** (`packages/fossflow-app`):
- **Mode detection:** `GET /api/platform/status`. With no backend, the app runs exactly as today (the static build, e.g. GitHub Pages). With a backend, it runs in platform mode.
- **Removed:** today's server-storage client and `/display/:id` (`services/storageService.ts`, `components/DiagramManager.tsx`, `StorageManager`). The backend no longer serves files, so they're replaced, not kept.
- **Routes (platform mode):**
  - `/setup`, `/signin`, `/invite/:token`, `/reset-password`;
  - an app shell with an n8n-style sidebar: Overview, Personal, Projects (with a + button for admins), Settings and a user menu;
  - `/home/landscapes` and `/home/credentials`;
  - `/projects/:id/{landscapes,credentials,settings}`;
  - `/landscapes/:id`: the editor with a slim header (breadcrumb, save state, sources picker, Export, live pill);
  - `/settings/{personal,users}`.
- **Editor saving:** autosave is a debounced `PUT`, 1.5 s after the last change. On a 409 conflict a banner offers "Reload" or "Overwrite".
- **Import:** JSON import creates a landscape.
- **Live polling:** `liveService` polls `/api/landscapes/:id/live`.
- **Dev:** the rsbuild dev proxy forwards all of `/api`.
- **Strings:** new text goes through i18n keys in `en-US`; other languages fall back to English until a later translation pass. *My call.*

**Deploy:**
- **compose.yml:**
  - Adds a `db` service (Postgres 18, volume, healthcheck) with `depends_on: service_healthy`, and a `./data:/data` volume.
  - New env vars: `DATABASE_URL`, `FOSSFLOW_URL`, and optional `FOSSFLOW_ENCRYPTION_KEY` and `SMTP_*`.
  - `ENABLE_SERVER_STORAGE` and the live-only fail-closed rule are removed, since login now protects everything.
  - Optional Basic Auth stays as an extra layer.
- **Dockerfile:** builds the server, prunes dev dependencies, and copies `dist`, `node_modules` and the migrations. It never copies `.env` (added to `.dockerignore`). The backend always starts on 127.0.0.1, behind nginx's `/api` proxy as today.
- **Breaking change, stated in the docs:** the Docker image now needs Postgres (compose provides it), and legacy data is migrated on first start.

## Milestones (each one tested, committed and pushed)

Branch `feat/platform-foundation`, stacked on `feat/design-system` because it needs the live layer and the design system, which aren't merged yet. A draft PR is opened once milestone 1 lands.

1. **Server skeleton.**
   - Nest 12 ESM app with config, Drizzle and migrations on boot, `/api/platform/status` and a health check.
   - The live module is ported, with its current environment-variable behaviour kept for now so the app keeps working.
   - Vitest set up, with integration tests against real Postgres via Testcontainers.
   - Postgres added to `compose.dev.yml`, the dev scripts updated, and the Docker build working.
2. **Authentication.**
   - First, a test-driven spike to settle server-side user creation. The docs leave open whether `signUpEmail` works with sign-up disabled. Fallback: better-auth's internal adapter plus its password hasher.
   - Then owner setup, sign-in and sign-out, the session guard, the origin check, invitations and the reset link.
   - App: mode detection, the setup, sign-in and invite pages, and the empty shell.
3. **Projects and RBAC.**
   - Roles and scopes seeded, the guard, personal projects, team projects and members.
   - App: projects in the sidebar, and the project settings page with members.
4. **Landscapes.**
   - CRUD, moving between projects, the 409 conflict check, autosave, import and export, and the legacy file migration.
   - App: Overview and project lists, and the editor page.
5. **Credentials and connectors.**
   - Encryption, the connector registry, the Beszel connector, credential CRUD with a test, the source manager, per-landscape live data, and migrating the Beszel `.env` login.
   - App: credential pages with forms generated from the connector descriptor, and the sources picker.
6. **Settings, deployment and docs.**
   - Users and personal settings pages.
   - compose, `.env.example` and the Dockerfile.
   - `docs/PLATFORM.md`, plus updates to `docs/LIVE.md` and the README.
   - Audit entries, and an end-to-end Docker walkthrough.

## Verification

- **Server:**
  - Vitest unit tests for crypto round trips and tamper detection, scope resolution, connector normalisation (the ported tests) and configuration.
  - Integration tests against real Postgres through Testcontainers:
    - setup only works once;
    - an invite works once and expires;
    - Viewer, Editor and Admin each get the right 403 and 200 responses on every endpoint;
    - the 409 conflict check;
    - credential values never appear in any response;
    - deleting a user transfers their data;
    - the legacy migration.
  - Target ≥80 % coverage of the new server code.
- **App:** a browser-pane walkthrough each milestone:
  - set up the owner;
  - invite a second user by copied link and sign in as them;
  - create a project and add members;
  - create, edit and autosave a landscape; force a conflict;
  - add a Beszel credential and run its test;
  - see live data on the landscape;
  - confirm a Viewer can't edit.
- **Local mode:** the static build with no backend behaves exactly as today. The existing Selenium e2e suite targets local mode and should stay green, but only if the Docker image for it is allowed back.
- **Docker:** a fresh `docker compose up` (Postgres plus app) goes through the full walkthrough. A second start migrates nothing twice. Losing the key file is reported clearly instead of producing garbage.
