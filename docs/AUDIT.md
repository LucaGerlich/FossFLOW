## 2026-11-09 — Real-Beszel fixes: faster stop detection, roomier plates

- **What:**
  - **Backend:** `normalize.ts` treats a container as stopped once its last report is more than 90 s older than its system's latest report (`CONTAINER_REPORT_LAG_MS`). The system `updated` timestamp is now fetched, and one shared timestamp schema accepts Unix ms or PocketBase date strings. The fake hub sets system timestamps.
  - **Lib:** auto-placed slots are 3 tiles apart instead of 2. Plate geometry derives from `SLOT_SPACING` and `PLATE_MARGIN` (`PLATE_WIDTH`).
- **Why:** Found while testing against a real Beszel 0.21.1 hub and agent in Docker.
  - Beszel keeps container records for 10 minutes, so a stopped container only became a ghost after about 10 min. Agents report every running container with each system report, which gives a much faster signal (about 1–2 min).
  - With real container names, labels of one row covered the metric chips of the row behind.
- **Security:** None.
- **Verified:** 38/38 backend tests pass (new: containers missing from the latest report are dropped). 21/21 live lib tests pass (updated coordinates, new real slot-occupancy test). Visually checked against the real hub: no label/chip overlaps.

## 2026-11-09 — Live bindings and automatic placement

- **What:**
  - Nodes and rectangles accept an optional `live: { key }` field (schema in `schemas/common.ts`, 1–300 characters).
  - New `live/types.ts` (mirrors the backend contract), a pure `live/sync.ts` (`syncLiveInventory`) and `live/LiveSync.tsx`, mounted by a new optional `<Isoflow live={snapshot}>` prop.
  - Pasted copies drop `live`. The compact export carries the key as an optional 4th field.
  - `RECTANGLE_DEFAULTS` excludes `live`.
- **Why:** Discovered servers and containers should appear on their own, and stay where people put them with their notes, across redeploys.
  - New server: a light plate to the right of existing content, with the server node in the first slot and its containers in a 4-column grid two tiles apart.
  - New container on a known server: the next free slot, growing the plate by one row when it's full.
  - Never moves or deletes anything. If a person deletes a server's plate, its new containers aren't placed loose.
  - Runs only in editable mode; read-only displays never change the diagram.
- **Security:** Keys are length-limited by the schema. Placement goes through the existing reducers and view validation, and errors are caught and logged without breaking the editor.
- **Verified:** Lib `tsc` is clean; 30/30 suites and 225/225 tests pass. New: 10 sync tests (first placement and model-schema validity, idempotence, next free slot, plate growth, hand-moved items kept, occupied slots skipped, deleted plate respected, multiple servers, unknown view) and 3 binding tests (schema, key limits, compact round-trip). Paste stripping is a two-line change in the clipboard hook, which has no test harness; it will be checked in the browser during end-to-end verification.

## 2026-11-09 — Hairline icon pack

## 2026-11-09 — Security: no CORS on `/api/live`; fail closed without auth

- **What:**
  - `server.js` mounts `/api/live` before the global `cors()` middleware, so live responses carry no `Access-Control-Allow-Origin` header.
  - `docker-entrypoint.sh` keeps live data disabled (it unsets `BESZEL_URL` and logs why) when Basic Auth isn't configured, unless `LIVE_ALLOW_UNAUTHENTICATED=true`.
  - `compose.dev.yml` sets that opt-out for local development, and `compose.yml` and `.env.example` document it.
- **Why:** Raised by an automated security review of the backend commit.
  - With the global `cors()` sending `*`, any website visited by someone on the same network could read the server and container inventory from an unauthenticated deployment via their browser.
  - Relying on optional Basic Auth was a documented assumption, not an enforced one.
- **Security:** Browsers now block cross-origin reads of the live inventory; the app reaches it same-origin (nginx in production, a dev-server proxy in development). The Docker image refuses to serve live data without auth in front unless the operator explicitly opts out. Deployments that run `server.js` directly must provide their own auth (to be documented in `docs/LIVE.md`). Not done: an app-level token or session, since v1 uses Basic Auth by decision.
- **Verified:** `curl` with `Origin: https://evil.example` shows no CORS header on `/api/live/status` while `/api/storage/status` behaves as before; `sh -n docker-entrypoint.sh`; 37/37 backend tests pass. The entrypoint behaviour is checked in the Docker verification step.

## 2026-11-09 — Deploy wiring for live data; service worker no longer caches the API

- **What:**
  - `public/service-worker.js` now ignores `/api/` and non-GET requests, and its cache name changed from `fossflow-v1` to `fossflow-v2`, which removes the old cache when the new worker activates.
  - `docker-entrypoint.sh` starts the backend when storage is enabled **or** `BESZEL_URL` is set.
  - The Dockerfile sets `BACKEND_HOST=127.0.0.1`. `compose.dev.yml` overrides it with `0.0.0.0` for its published dev port and passes the `BESZEL_*` variables.
  - `compose.yml` and `.env.example` document `BESZEL_URL`, `BESZEL_EMAIL`, `BESZEL_PASSWORD` / `BESZEL_PASSWORD_FILE` and `LIVE_POLL_SECONDS`.
- **Why:** The service worker served every same-origin GET from cache first, `/api/*` included, so live data would have frozen on its first response; diagram listings were also cached. Live data needs the backend even when diagram storage is off.
- **Security:**
  - Inside the image the backend now listens only on localhost, so the live inventory and diagram API are reachable only through nginx, behind Basic Auth when configured. Other containers on the same Docker network can no longer reach them on port 3001 directly.
  - Stale cached API responses are removed from browsers.
  - Not changed: `compose.dev.yml` still publishes 3001 directly, for development only.
- **Verified:** `sh -n docker-entrypoint.sh`, `node --check service-worker.js` and `docker compose config` pass for both compose files. The full image is built and checked end to end in the verification step.

## 2026-11-09 — Backend: Beszel live source and `/api/live`

- **What:**
  - New `packages/fossflow-backend/live/` module in strict TypeScript, run directly by Node 24 (type stripping, no build step):
    - `config.ts` validates the environment.
    - `beszel.ts` is a read-only PocketBase client.
    - `normalize.ts` holds the status rules and container kinds.
    - `hub.ts` handles polling, the last good snapshot and 60 samples of history.
    - `routes.ts` serves `GET /api/live/status` and `/snapshot`.
    - `testing/fakeBeszel.ts` is a fake hub used by the tests and by `npm run dev:fake-beszel`.
  - `server.js` mounts the router and sets `trust proxy` to `loopback`.
  - Added `zod` (already in the monorepo), `@types/node` and `@types/express`; new `test`, `lint` and `dev:fake-beszel` scripts.
- **Why:** The first live source for the map: servers, running containers and vitals from a team's existing Beszel hub, so nothing new has to be installed on servers.
- **Security:**
  - Credentials come only from the environment (`BESZEL_PASSWORD` or `BESZEL_PASSWORD_FILE` for Docker secrets) and never appear in logs, error messages or API responses (tested).
  - The outbound URL is fixed by configuration, so requests can't be redirected to other hosts (no SSRF), and it is rejected if it embeds credentials.
  - Every Beszel response is validated with zod; malformed records are skipped and counted.
  - Requests time out after 10 s.
  - `/api/live/*` is rate-limited (120/min), sends `Cache-Control: no-store` and sits behind the deployment's auth (nginx Basic Auth).
  - `trust proxy: loopback` makes the new and existing rate limits count per client behind nginx instead of one shared bucket.
  - The snapshot contains no hostnames or IPs of the Beszel hub or agents.
  - Use a Beszel `readonly` user.
- **Verified:** `tsc -p packages/fossflow-backend` is clean; 37/37 `node:test` tests pass (config validation, token reuse, re-login after 401, wrong credentials, unreachable hub, malformed records, pagination past 500, status rules, kind detection, stale containers, snapshot without secrets, last good snapshot kept during an outage, history). Smoke-tested the real `server.js` against the fake hub with `curl`; `/api/storage/status` is unchanged.
